### Compact frontend writes

- `portal/src/infrastructure/stateChanges.ts` computes add/remove/replace changes using JSON Pointer paths. It excludes server-controlled history, identity, ownership and version fields.
- `remoteRepository.save(next, previous)` sends PATCH `/api/workspaces/{id}` with `If-Match`, not a full workspace PUT.
- Backend `StateChanges.cs` applies bounded changes; existing authorization, validation, transaction, history and concurrency logic remains in effect.
- PATCH returns `{ version, changes }` relative to the original snapshot. The frontend applies this canonical delta locally, with no full reload after saving.
- Full PUT remains as a compatibility/import endpoint. The dedicated POST card endpoint also remains; related UI operations use atomic workspace PATCH changes.
- Conditional workspace GETs use `If-None-Match`. Authorized unchanged reads return 304 and no body. Snapshots are cached in application memory separately per account/workspace. HTTP caching is disabled (`private, no-store`) to avoid account crossover.

### Workspace mapping performance fix

`api/Workspaces/WorkspaceMapper.cs` previously repeatedly accessed DbSet.Local and scanned full relationship collections inside per-card/per-history loops, causing repeated EF change detection and excessive work.

Changes:

- Build association lookups once for card labels, assignees, comments, checklists, history entries, history changes and attachments.
- Use a member-name dictionary rather than repeated member searches.
- Temporarily disable automatic change detection during read mapping and explicit synchronization, restoring the prior setting in `finally`.
- Preserve normal save-time change detection, validation and optimistic concurrency.

Local application-service results after the fix:

- 500 cards: read 0.38s; read/validation/serialization 0.39s; 883691 response bytes. Previous read/validation took 88.30s.
- 2500 cards: read 0.71s; total 0.79s; 4332402 bytes.
- 5000 cards (Delivery): read 0.91s; total 1.15s; 8597071 bytes.
- 5000 cards (Operations): read 0.63s; total 0.84s; 8597071 bytes.
- 7000 cards: read 0.86s; total 1.15s; 12010739 bytes.

These are local service measurements, not end-to-end browser timings or concurrency benchmarks.
